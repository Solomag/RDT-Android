# План порта RDT на Android

Статус: в работе. Текущая веха — M1 (проверка на телефоне) → M2 (2026-11-13).

**Ход работ**
- M0: готово. Таблица методов: `C:/tr/r/docs/rdt-m0-methods.md`. AddHistoryQueue и HistoryQueue.Parser есть. `ToByteArray` вырезан, поэтому сериализация идёт через CalculateSize + CodedOutputStream(byte[]) + WriteTo + Flush. Колоды и карты лежат там же, где на ПК.
- M1: каркас RDT-Android готов, загрузчик в порте написан (hook/32-rdt-loader.ts; не проверен на телефоне, не запушен). API `teslPort` и порядок включения описаны в `docs/loader-contract.md`. Канал ждёт публичный ключ (keygen делает пользователь). Публичный репозиторий: github.com/Solomag/RDT-Android.

## Исходные данные

**Android-сборка игры** (со слов сессии TESL_Reborn_Android, репозиторий `C:\tr\r`):
- IL2CPP, Unity 2017.4, только arm64-v8a. C#-плагины (BepInEx/Harmony) не загрузить.
- Имена типов те же, что на ПК. Подтверждены: BoardConductor, BoardState, MatchUI, LocalizationManager, GameNetworkManager, GameData, PlayerInfoPanel.
- Загрузчик уже есть:
  - frida-gadget с frida-il2cpp-bridge, хук на TypeScript (`hook/*.ts`);
  - Builder пересобирает APK пользователя, root не нужен;
  - обновления скрипта приходят с GitHub (OTA).
- Переподписанные APK играют на серверах Reborn без проблем.
- Что можно переиспользовать:
  - помощники для uGUI (`uiNew/uiPlace/uiText/uiButton`);
  - клонирование окон игры (`27-chat.ts`);
  - история матча (`26-history-and-match-intro.ts`);
  - статистика колоды (`15-deck-statistics.ts`).

**ПК-версия:** около 8200 строк C#. Ядро подсчёта: Events 1400, Opponent 430, Deck 290, Turn 270, Picker 260, GameData 640, DeckClassifier 340.

## Решения

1. **Не прямой порт, а переписывание на TypeScript.** Трекер становится модулем Android-хука и использует его загрузчик, обновления и Builder.
2. **Модуль опциональный.**
   - По умолчанию выключен, включается переключателем в настройках порта.
   - При включении скачивается с GitHub из публичного места: отдельный репозиторий или ассеты релиза. Исходники ПК-версии остаются приватными.
   - Скачанный код проверяется подписью (ed25519). Публичный ключ зашит в загрузчике, и модуль без верной подписи не запускается.
3. **Ядро отделено от игры.**
   - Подсчёт работает на простых JS-объектах.
   - Отдельный адаптер переводит объекты IL2CPP (HistoryQueue, карты, позиции) в эти объекты.
   - Тот же формат даёт парсер записей в Node, поэтому ядро можно тестировать на ПК без телефона.
4. **Эталон — ПК-версия.** Одна и та же запись матча (`.rdtrec`) прогоняется через ПК-трекер (in-game replay) и через TS-ядро. Ключевые строки лога должны совпасть:
   - `Events: -` / `+` / `x`;
   - `MODCHECK`;
   - `CHECK:`.

## Этапы

### 0. Проверка (1–2 дня)
- **Найти в дампе игры:**
  - `LogMessageTranslator.AddHistoryQueue`, `CcgRpc.HistoryQueue` (+ `Parser`);
  - `Google.Protobuf.MessageExtensions.ToByteArray`;
  - `CardListPicker`, `CardListItem.SetData`, `MatchUI.SetCardListPickerData`;
  - `PlayerInfoPanel.SetPlayerDeckIconInteract`, `GameNetworkManager.SendCheat`;
  - инвентарь колод (то, что читает `MatchTracker.Deck.cs`).
- **Выяснить**, что уже перехватывает `26-history-and-match-intro.ts`, чтобы два хука не мешали друг другу.
- **Решить**, где живёт модуль: в репозитории порта или отдельно.

Результат: список методов с пометкой «есть / нет / другое имя».

### 1. Запись матчей (2–3 дня)
- **На телефоне:**
  - хук на `AddHistoryQueue`, `ToByteArray`, запись в тот же формат `.rdtrec`: чанки `[тип][int32 длина][данные]`, заголовок `local/deck/code/name`;
  - файлы кладутся в папку приложения, оттуда их можно забрать через `adb pull`.
- **На ПК:** запись с телефона копируется в `%APPDATA%\RebornDeckTracker\replays\`, replay через `replay-request.txt`.

Результат: несколько Android-матчей проходят через ПК-трекер с `CHECK: OK`. Это доказывает, что поток сообщений на телефоне тот же, что на ПК.

### 2. Стенд для тестов в Node (2–3 дня)
- `.proto` для HistoryQueue, восстановленный по дампу (поля, которые использует трекер), и protobufjs.
- Парсер `.rdtrec` → те же простые объекты, что даёт адаптер на телефоне.
- **Эталоны:**
  - набор записей (ПК и Android);
  - `replay-result.txt` от ПК-трекера по каждой записи;
  - нормализатор, который оставляет только ключевые строки.

Результат: `npm test` прогоняет все записи.

### 3. Ядро подсчёта на TS (1,5–2 недели)
Переносить в таком порядке, после каждого шага прогоняя тесты:

1. Зоны и uid. Добор и возврат: `MarkLeft`, `EnteredDeck`, сверка с серверным счётчиком (`Reconcile`).
2. Полное состояние: переподключение, а также полное состояние посреди матча после дебаг-команд.
3. Украденные и созданные карты, изгнанные карты, карты оппонента (`Opponent.cs`), возврат в руку.
4. Изменения карт в колоде: баффы из текста, стоимость, возвраты Shadowmere, `MODCHECK`.
5. Определение колоды оппонента: `DeckClassifier`, `decktypes.txt`, профили, боты из `bots-v1.json`.
6. Сохранение `pools.txt` и часов для перезапуска посреди матча.
7. Дебаг-меню: хук `SendCheat`, пометка матча.

Таблицу локализации вынести из `Localization.cs` в общий файл (TSV или JSON), чтобы обе версии читали один источник.

Результат: на всех записях ключевые строки совпадают с ПК, кроме оговорённых расхождений.

### 4. Интерфейс (1–1,5 недели)
- **Минимум:**
  - колода в нативном окне списка карт со счётчиками (`осталось/всего` или только остаток), отдельными строками для изменённых копий и скрытием ушедших карт;
  - окно оппонента;
  - кнопки колоды у аватаров;
  - настройки: язык, режим счётчика, показ ушедших карт.
- **Под касание:** вместо наведения — нажатие; кнопки крупнее.
- **Производительность:**
  - пересчёт и перерисовка только по новому сообщению, а не каждый кадр;
  - строки окна переиспользуются;
  - тяжёлую работу укладывать в рамки покадрового ограничителя хука, который уже есть в порте.
- **Позже:** кривая маны, метки на поле, окна сбросов и созданных карт.

Результат: полный матч на телефоне без заметных просадок FPS; список совпадает с подсчётом.

### 5. Статистика и загрузка (3–5 дней)
- `games.jsonl` и счётчик побед и поражений по колоде. Дебаг-матчи в статистику не идут.
- Отправка на tesl-decks.com: через `httpGetBytes` порта или UnityWebRequest; очередь и повторные попытки.
- **Токен:** поле в настройках модуля, хранится в папке приложения. Ни в логи, ни в записи матчей он не попадает.
- Данные Reborn после матча (`RebornStats`).

### 6. Выпуск (2–3 дня)
- Подписанный релиз модуля. Переключатель в настройках порта, загрузка и OTA.
- **Проверка совместимости при старте:** если нужного метода нет, функция тихо отключается и пишет в лог, а не ломает игру.
- Короткая инструкция для пользователей порта.

## Сроки
В сумме 4–6 недель неспешной работы. Самые длинные этапы — ядро (3) и интерфейс (4).

## Риски
- **Производительность Frida.** JS выполняется в одном потоке, а каждое обращение к объектам IL2CPP стоит дорого. Меры:
  - адаптер читает только нужные поля, один раз на сообщение;
  - ядро работает с простыми объектами.
- **Расхождение версий.** Каждое исправление в ПК-ядре нужно повторять в TS. Тесты на общих записях покажут, где версии разошлись.
- **Обновления игры.** Это касается обеих версий. Помогает проверка совместимости при старте (этап 6).
- **Безопасность загрузки.** Код из сети выполняется внутри игры, поэтому подпись обязательна, а URL зашит в загрузчике.

## Принятые решения (2026-11-13)
1. **Модуль живёт в отдельном репозитории `RDT-Android`** (папка `E:\RDT-Android`).
   - Исходники лежат там; в релизах — собранный и подписанный `rdt.js`.
   - В репозиторий порта (`C:\tr\r`) идёт только маленький загрузчик модуля: переключатель в настройках, скачивание, проверка подписи, запуск.
   - Почему отдельно:
     - у модуля свой цикл выпусков и свои тесты (Node, эталонные записи);
     - тем, кто трекер не включал, ничего не скачивается;
     - порт не зависит от трекера, и наоборот.
2. **Три сессии:**
   - **Координатор (форк этой сессии, новый)** — пишет TS-модуль в `E:\RDT-Android`, держит этот план и связывается с двумя другими сессиями.
   - **ПК (эта сессия)** — эталон:
     - replay записей с телефона;
     - эталонные логи;
     - исправления ПК-ядра, которые нужно повторить в TS.
   - **TESL_Reborn_Android** — порт:
     - дамп типов, проверка методов (этап 0);
     - загрузчик модуля в хуке и переключатель в настройках;
     - сборка APK, ключ подписи модуля.
3. **Интерфейс — всё, что есть в ПК-версии,** по очереди (см. M4–M6).
4. **Загрузка на tesl-decks.com отложена.** `games.jsonl` и локальная статистика остаются.

## Правила совместной работы
- Сессии общаются сообщениями, план живёт в этом файле. Координатор переносит его в `RDT-Android/docs/plan.md` и дальше ведёт там.
- **Любое исправление ПК-ядра:** ПК-сессия сообщает координатору коммит и запись, которая его ловит. Запись добавляется в эталоны.
- **Записи матчей с телефона** забираются через `adb pull`. Перед тем как попасть в репозиторий, они проверяются на личные данные: в заголовке не должно быть ничего, кроме uid, колоды и её кода.
- **Ключ подписи модуля** хранится у пользователя, не в репозитории. Публичная часть зашивается в загрузчик порта.
